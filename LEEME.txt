Standalone Netlify site for the Eth Sanglier staff app.
No npm packages: you can still drag this folder onto Netlify, or link the GitHub repo for automatic deploys.

1. Drag this whole folder (or the zip) onto the Netlify project's Deploys page
   (or: Project configuration > Build & deploy > Link repository > github.com/1d1l10/sanglier, no build command, publish directory ".").

2. Project configuration > Environment variables. Mark the keys/tokens as "secret".

   Required
     AIRTABLE_TOKEN    same token the website uses (read+write on base appCPMJQxYGMUZwOu)
     AIRTABLE_BASE_ID  appCPMJQxYGMUZwOu
     STAFF_SECRET      any long random text. Changing it signs EVERYONE out.
     LAIA_WHATSAPP     digits only, e.g. 34600123456

   Recommended
     PIN_PEPPER        another long random text, used to hash the PINs. Set it BEFORE the first deploy of this
                       version and never change it afterwards (if missing, STAFF_SECRET is used; then never change that).

   Push notifications on the phones (free)
     VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY   run once:  node scripts/vapid-keys.mjs   and paste both. Never change them.
     VAPID_SUBJECT     optional, e.g. mailto:info@ethsanglierskischool.com

   WhatsApp (choose one provider)
     WA_PROVIDER       meta | twilio
     Meta:   WA_TOKEN, WA_PHONE_ID, WA_TEMPLATE (default aviso_clases), WA_LANG (default es)
     Twilio: TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_WA_FROM (e.g. 14155238886) or TWILIO_MESSAGING_SERVICE_SID,
             TWILIO_TEMPLATES = {"aviso_clases":"HX...","recordatorio_7d_es":"HX...", ...}  (Content SIDs of approved templates)

   Email (Resend): RESEND_API_KEY, MAIL_FROM, MAIL_REPLY_TO (optional)
   Sending switches: NOTIFY_ON=1, NOTIFY_DRYRUN=1 (test), NOTIFY_CLIENTS=1, NOTIFY_CLIENT_WA=1 (see netlify/lib/staff-notify.mjs)
   Client reminders: NOTIFY_CLIENT_AT (default 10:00, the 7-day one), NOTIFY_CLIENT_NIGHT (default 19:00, the evening-before one),
                     NOTIFY_CLIENT_KINDS (default "c7,c1"; add ",c2h" for one 2 hours before each class)

3. Deploy again after adding variables (Deploys > Trigger deploy), then open /staff/
4. Functions list should show: staff, notify.

Security, in short
- The PIN stays 4 digits (gloves). Protection is on the server: PINs are stored hashed in Airtable (never readable,
  not even by the admin screen), 5 wrong PINs lock a connection for 15 min, 30 wrong PINs in an hour lock the PIN
  screen for 20 min and alert the admins by push. Counters live in the Airtable table "Accesos" (delete a row to unlock).
- Changing someone's PIN signs that person out on every phone. Deactivating a profile cuts access immediately.
- After this version is deployed everyone has to type their PIN once more.

Push notifications for the team
- Each person taps the bell (🔕) at the top of the app > "Activar notificaciones".
- iPhone: first Safari > Share > "Add to Home Screen", open the app from that icon, then tap the bell.
- The admin sees in Avisos who has it switched on ("Móvil · 1 dispositivo").

Reminders to clients (paid bookings only, by email, and by WhatsApp if NOTIFY_CLIENT_WA=1)
- 7 days before: "we are waiting for you" + a button to tell Laia on WhatsApp anything they need for the class.
- The evening before: how to get there: exact map, the directions of that meeting point, Laia's phone.
- Directions per meeting point: Airtable table "Puntos de encuentro" (one line per tip, ES/EN/FR/CA, exact Google Maps link).
  The name must appear in the booking's "Punto de encuentro". Changes apply at once, no deploy.
- WhatsApp needs one approved template per reminder and language: recordatorio_7d_es, recordatorio_1d_es, … (_en, _fr, _ca)
  with 4 variables: {{1}} name, {{2}} day and time, {{3}} meeting point, {{4}} link (7d: Laia's WhatsApp; 1d: map).

Tests (no network): node --test tests/*.test.mjs
